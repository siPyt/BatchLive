DECISIONS / HONESTY BOUNDARIES (carried into every faceplate change)
----------------------------------------------------------------------
- Modelock Override: rendered as a real checkbox matching the reference
  layout, but disabled with an explicit tooltip explaining Equipment
  Module/Phase acquire-release arbitration (C_ARB_MOD_EM/PH) is not
  modeled yet. This is a visual-fidelity placeholder, not a claim of real
  arbitration — consistent with the Pass60 decision already recorded in
  GRAPHICS-APPEARANCE-AND-BEHAVIOR.txt.
- Owned by: explicitly says "Not modeled". Static `equipmentModule`
  membership, when present, is shown separately as "Equipment Module:".
  Recovery corrected the interrupted draft's misleading ownership label,
  honoring the existing graphics contract's Pass60 boundary.
- Unit: no Unit-module concept exists in this simulator; always renders an
  em-dash. Documented, not hidden.
- Speed Information (Auto SP/Remote SP/PV%) block from IMG_0639 is NOT
  reproduced on MotorModule faceplates: this simulator's MotorModule is a
  confirmed-running/stopped discrete device (DC1/DCC template), with no
  modeled variable-speed-drive feedback loop. Adding those numbers would be
  a fabricated reading, not a real one. Documented as an explicit boundary.
- Device State / Operation State / Failure State text is derived 100% from
  existing real fields (dcState, interlock, permissiveRequired/permissiveOk,
  fault) — only the *labels/wording* change to match DeltaV's phrasing
  ("Confirmed Running", "Interlocked", "Faulted", etc.); no new simulated
  state is introduced.
- Mode (MAN/CAS) shown on Motor/Valve faceplates is derived from the
  existing `commandSource` field (set = an interlock/FB tag is driving the
  command automatically = CAS; unset = direct operator Start/Stop/Open/
  Close = MAN) — an honest real distinction already in the engine, just
  newly surfaced with DeltaV's own DCC-template vocabulary.
